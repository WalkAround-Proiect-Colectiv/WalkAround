# Local city airports

[`CityAirportServiceImpl`](CityAirportServiceImpl.java) backs `GET /api/trip-plans/cities/{city}/airports?countryCode=XX`. It reads municipalities in the requested country, finds matching municipality IDs in Java, then fetches their airports with `AirportRepository`. The city name is a regular URL path value: clients must URL-encode spaces and non-ASCII characters.

Matching has two stages:

1. Compare the normalized base name without folding accents. The base-name step removes trailing parenthetical text and slash suffixes, so `City`, `City (something)`, `City/something`, and `City / something` can all belong to the same exact match.
2. If stage one finds nothing, compare folded keys from [`CityNameNormalizer`](../utils/CityNameNormalizer.java). This handles many Latin/Greek diacritics, selected letter variants, and punctuation. If folded matching points to different exact base names, the service raises `AmbiguousCitySelectionException` instead of silently choosing one.

The repository query is intentionally simple; the normalization is performed in Java, so PostgreSQL `unaccent` is not required. [`GeoNamesCityLocationProvider`](GeoNamesCityLocationProvider.java) validates the selected city and country and obtains its coordinates from a populated-place result. The service returns the municipality matches first (`matchType=CITY`), then up to `nearbyAirportMaxResults` other airports within `nearbyAirportRadiusKm` of the city coordinates (`matchType=NEARBY`). The nearby repository query restricts airports to the selected city's country code, so airports across a border are excluded even when they are within the radius. Nearby results are ordered by straight-line distance and contain only airports with IATA codes. Each response includes the airport's `countryCode`. `distanceKm` is the straight-line distance from the GeoNames city center, rounded to one decimal; it is not road travel distance or a claim that the airport officially serves the city. Airport IDs deduplicate the two groups. The service returns `[]` when a valid city has no matching or nearby airport. A city that GeoNames cannot validate produces `400`, and a GeoNames failure produces a generic `502`. A city airport may have a null IATA code because the database column is nullable.

The import script `scripts/airports_data/import_airports.py` currently loads EU member countries and **large airports only**. This endpoint describes that local dataset; it is not the destination-airport resolver for flight search, which instead passes a Google Flights city ID to SerpApi.

The saved-plan service reuses `CityAirportService.findAirports` when creating a plan. It verifies that the chosen origin IATA code appears among the selected GeoNames departure city's city or nearby airport results. The saved departure city and country code can be used with this lookup again when the user wants another origin airport.
