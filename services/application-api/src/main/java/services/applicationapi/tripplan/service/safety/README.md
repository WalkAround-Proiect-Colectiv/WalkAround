# Destination safety information

`SafetyInformationService` validates the requested city and two-letter country code before any Travel Risk API call. It reuses `AccommodationCityValidator`, which checks a populated GeoNames city in geographical Europe and returns the matched name, country, and coordinates. Invalid input gives `400`; unavailable GeoNames or Travel Risk API data gives a generic `502` through the controller advice. The service depends on `SafetyInformationProvider`, so a different safety source can be implemented without changing the endpoint or validation.

`TravelRiskSafetyInformationProvider` follows the [official risk API reference](https://travelriskapi.com/docs/risk). It sends the private key in `X-API-Key` to three read-only endpoints: `/api/v1/advisories`, `/api/v1/alerts`, and `/api/v1/conflicts`. All requests filter by the validated country code. One user check makes one GeoNames request and three Travel Risk API requests. No provider calls occur merely because the trip-planning page renders or a city is typed. The provider checks that each response contains its documented `data` list; a failed or incomplete feed fails the whole check rather than implying that no risks were found. Raw provider errors, key values, and request URLs do not reach the client or logs.

Advisories are country-wide agency assessments, with the highest level and individual source labels. Alerts are active natural-hazard and weather reports. Conflicts are recent reports from the provider's default seven-day window. For alerts and conflicts, the backend requests the provider's maximum first page (`limit=1000`), excludes entries without valid coordinates, and keeps reports within `SAFETY_NEARBY_RADIUS_KM` of the GeoNames city center (default 100 km). It ranks Critical and High before lower severities, then nearer reports, returning up to `SAFETY_MAX_RESULTS` per list (default 10). `alertsPartial` and `conflictsPartial` indicate that more country records exist than were fetched, or that more nearby records matched than the application returned. They do not guarantee that all nearby reports were seen.

The response includes a check timestamp and the applied radius. It stores no safety data in the database and sends `Cache-Control: no-store`. External source URLs are included only when they use HTTPS without credentials or API keys. An empty nearby list means no geolocated report was found in the retrieved country data within the configured radius; it is not a declaration that the city is safe. The frontend shows advisories separately from nearby reports and lets the user refresh explicitly.
