# Destination weather forecast

`WeatherForecastService` validates a destination city and two-letter country code, then reuses the GeoNames city validator to obtain trusted coordinates. Invalid city input or an unmatched city/country pair returns `400`; unavailable GeoNames or Open-Meteo data returns a generic `502`. The client receives no upstream error body.

`WeatherForecastProvider` keeps the service independent of a weather source. The Open-Meteo implementation requests `/v1/forecast` once per user action with `latitude`, `longitude`, `timezone=auto`, and configured `forecast_days` (default and maximum 14). It reads daily weather code, maximum/minimum Celsius temperature, maximum precipitation probability, precipitation total in millimeters, and maximum wind speed in km/h. It requires aligned daily arrays and valid ISO dates. The response preserves the destination timezone and daily dates for local-day display.

The forecast API always returns the next forecast days from the destination's present local date, regardless of any trip date. The frontend highlights the selected check-in date and staying nights only where they overlap the returned window and explains when a trip is later or only partly covered. The free Open-Meteo endpoint needs no API key. See [Open-Meteo forecast documentation](https://open-meteo.com/en/docs) and [usage terms](https://open-meteo.com/en/pricing).

`HistoricalWeatherService` separately validates the selected city, ISO check-in date, and 1–365 nights. It chooses the configured number of most recent completed comparable stays before the present, preserving the whole stay length and crossing year boundaries when needed. A five-day archive lag avoids asking for dates that might not yet be available. Feb 29 is moved to Feb 28 in non-leap comparison years by Java's `minusYears` behavior.

`HistoricalWeatherProvider` keeps archive lookup separate from the service. Its Open-Meteo implementation calls `/v1/archive` once per comparison year with inclusive start/end dates, `timezone=auto`, and daily weather code, maximum/minimum temperature, precipitation total, and maximum wind. Historical data does not offer a rain-probability field. Each response must contain exactly one aligned day per night in the chosen stay; partial or malformed data produces a generic `502` instead of a misleading comparison. This is historical reanalysis, not a prediction or the original past forecast. See [Open-Meteo Historical Weather documentation](https://open-meteo.com/en/docs/historical-weather-api).
