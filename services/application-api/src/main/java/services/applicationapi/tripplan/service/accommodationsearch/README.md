# Accommodation search

`AccommodationSearchService` is the controller-facing interface for `POST /api/trip-plans/accommodation-searches`. `AccommodationSearchServiceImpl` coordinates validation, provider results, EUR budget filtering, ascending total-price sorting, and the configured result limit. `AccommodationCityValidator` and `AccommodationSearchProvider` keep GeoNames and SerpApi replaceable without changing the service or API contract.

## Request and validation

The request contains `destinationCity` and `countryCode` from a GeoNames city suggestion, `checkInDate` (first booked night), `stayingNights`, and a total EUR `budget`. Check-out is `checkInDate + stayingNights`. Bean Validation checks required fields, country-code shape, positive budget, and 1–365 nights. The service rejects past check-in dates, impossible check-out dates, and invalid city text.

`GeoNamesAccommodationCityValidator` verifies a populated place (`featureClass=P`) with the requested name and country code in geographical Europe (`continentCode=EU`). Name comparison uses `CityNameNormalizer` for spelling variants, including diacritics. The country code comes from the autocomplete option; the endpoint still validates it against GeoNames rather than trusting the client. This covers geographical Europe, including countries outside the EU member-country table used by flight search. A selected city is represented by its name and country code, so two same-named places in one country cannot be distinguished by this request.

## SerpApi request and prices

`SerpApiAccommodationSearchProvider` makes one `google_hotels` list request with the validated `City, Country` query, check-in/check-out dates, `currency=EUR`, `adults=1`, and lowest-price sorting. The property-details requests also use `adults=1`, so displayed prices and booking options are evaluated for one adult. The application inspects only the returned first page; it does not promise the cheapest available property across all pages.

Only list properties with a positive `total_rate.extracted_after_taxes_fees` and a `property_token` are eligible. That price represents the entire stay including taxes and fees. Properties without it are skipped because their total cost cannot be compared reliably with the budget. The service sorts affordable properties and selects at most `ACCOMMODATION_SEARCH_MAX_RESULTS` (default `3`). It then makes one property-details request for each selected property, using its token and the same dates and currency. **One application request makes at most `1 + ACCOMMODATION_SEARCH_MAX_RESULTS` SerpApi searches** plus one GeoNames request; with the default limit, at most four SerpApi searches. There is no pagination or automatic replacement of a selected property whose details lack a bookable rate. Identical SerpApi searches may be served from its cache without using a plan credit.

The detail response adds description, address, overall rating, review count, amenities, available `roomTypes` names, and `bookingOptions`. Room names come from featured price entries and do not identify the room for a particular booking option. Each booking option contains its source, tax-and-fee-inclusive full-stay EUR price, and an HTTPS booking-site URL. Only options within the budget are returned, sorted by price and limited to the configured result count per property. If an eligible booking option exists, the offer's `totalPrice` is the cheapest such option. Otherwise it uses the detailed property total when available, falling back to the initial list total, and `bookingOptions` is empty. A property is skipped if the detailed total exceeds the budget or its available booking options are all over budget. The optional `propertyWebsiteUrl` is the property's own website, not necessarily a booking link. Booking prices and availability can change after the search; the endpoint does not purchase or reserve a room. SerpApi's `max_price` filter is not used because it does not document whether that bound applies to the full stay; the application enforces its budget against the returned total.

## Failures and settings

The provider accepts `search_metadata.status=Success`, including an empty result set, and treats other or missing statuses as upstream failures. A failed property-details request fails the whole accommodation search with a generic `502`; successful detail responses may have empty optional fields. External error text, URLs containing API keys, and raw provider responses are not returned to clients. The controller maps invalid requests to `400`, provider failures to a generic `502`, and unexpected failures to `500`.

`AccommodationSearchProperties` owns the SerpApi key and result limit. The provider reuses the existing `serpApiRestClient` and `geoNamesRestClient` beans for their configured base URLs and timeouts. `ACCOMMODATION_PROVIDER` selects the provider implementation; to switch providers, implement `AccommodationSearchProvider` and configure the selection. See the [configuration README](../../configurations/README.md) for environment settings.
