# Attraction recommendations

`AttractionSearchService` is the controller-facing interface for paged tourist attraction recommendations. The service checks the city path, two-letter country code, and zero-based page number (`0` through `5`). It uses the GeoNames-backed `AccommodationCityValidator` to confirm a populated place in geographical Europe. That validator also supplies latitude and longitude for the SerpApi request. Name comparison accepts spelling variants through `CityNameNormalizer`.

`AttractionSearchProvider` hides the external search engine. `SerpApiAttractionSearchProvider` makes one Google Maps `type=search` request for each requested page, with a city-and-country query, `ll=@latitude,longitude,14z`, and `start=page*20`. SerpApi requires `ll` for pagination. The provider reads `local_results` and `serpapi_pagination.next`; it never follows the next URL or place-detail links. The API response contains `items` and a nullable `nextPage`. The next page is absent when SerpApi has no next page or page 5 has been reached. This caps the provider offset at 100, following SerpApi's recommendation. Each application request makes at most one SerpApi search plus one GeoNames validation request. Additional pages are fetched only when the user requests them.

The service returns all usable `local_results` from each provider page in provider order. Google Maps commonly supplies about 20 results per page; the actual count depends on SerpApi. No application result cap truncates a page, so recommendations are not skipped when the user advances to the next provider page. An empty successful provider page gives empty `items`; missing or non-`Success` `search_metadata.status` is an upstream error. Provider error text, raw URLs, and the API key are not sent to clients or logged.

Each item can include a name, category, address, description, rating, review count, coordinates, a Google Maps search URL, an optional image URL, and an optional website URL. The provider constructs the Maps URL with the place ID when available, accepts only HTTPS image and website links without credentials or API key query parameters, and omits invalid coordinates. Recommendations may include places outside the exact city boundary because Google Maps does not guarantee municipal-boundary membership.
