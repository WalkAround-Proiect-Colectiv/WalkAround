# Trip planning HTTP endpoints

Controllers delegate to service interfaces. The `exceptionhandlers` package contains controller-specific `@RestControllerAdvice` classes that return `ProblemDetail` responses; upstream error details and credentials are not sent to clients.

| Method and path | Input | Successful response |
| --- | --- | --- |
| `GET /api/trip-plans/cities?city=Par` | City-name prefix | `List<CitySuggestion>` from GeoNames. |
| `GET /api/trip-plans/cities/{city}/airports?countryCode=FR` | Selected city name and two-letter country code | `List<AirportResponse>` from the local database. URL-encode the city path segment, including spaces and non-ASCII characters. |
| `GET /api/trip-plans/cities/{city}/attractions?countryCode=FR&page=0` | Selected GeoNames city, two-letter country code, and optional zero-based page (`0` to `5`, default `0`) | `PlaceRecommendationPageResponse` with `items` and nullable `nextPage`. URL-encode the city path segment. |
| `GET /api/trip-plans/cities/{city}/restaurants?countryCode=FR&page=0` | Same city, country, and page parameters | `PlaceRecommendationPageResponse` for restaurants, with the same paging and place fields. |
| `GET /api/trip-plans/cities/{city}/museums?countryCode=FR&page=0` | Same city, country, and page parameters | `PlaceRecommendationPageResponse` for museums, with the same paging and place fields. |
| `GET /api/trip-plans/cities/{city}/coffee-shops?countryCode=FR&page=0` | Same city, country, and page parameters | `PlaceRecommendationPageResponse` for coffee shops, with the same paging and place fields. |
| `GET /api/trip-plans/cities/{city}/safety?countryCode=FR` | Selected GeoNames city and two-letter country code | `DestinationSafetyResponse` with country advisories and nearby alerts/conflicts. URL-encode the city path segment. |
| `GET /api/trip-plans/countries/{countryCode}/hotlines` | Two-letter EU destination country code | `CountryHotlineResponse` with one item per hotline and typed numbers from the local database. The selected city supplies its country code on the frontend. |
| `GET /api/trip-plans/cities/{city}/news?countryCode=FR` | Selected destination city and EU country code | Up to the configured page size of `NewsArticleResponse` objects with publisher links. URL-encode the city path segment. |
| `GET /api/trip-plans/cities/{city}/weather?countryCode=FR` | Selected GeoNames city and two-letter country code | `DestinationWeatherResponse` with up to 14 destination-local forecast days. URL-encode the city path segment. |
| `POST /api/trip-plans/flight-searches` | JSON `FlightSearchRequest` | Up to the configured number of `FlightItineraryResponse` objects. Search is read-only; it creates no trip or booking record. |
| `POST /api/trip-plans/accommodation-searches` | JSON `AccommodationSearchRequest` | Up to the configured number of `AccommodationOfferResponse` objects. Search creates no booking. |
| `POST /api/trip-plans` | JSON `SaveTripPlanRequest` and authenticated JWT | `201 Created`, `Location: /api/trip-plans/{id}`, and `TripPlanResponse`. |
| `GET /api/trip-plans/{id}` | Plan UUID and authenticated JWT | `TripPlanResponse` for the current owner, or `404`. |

The flight-search JSON uses `originAirport` as a three-letter IATA code, `destinationCity`, a two-letter `countryCode`, a positive EUR `budget`, `departureFrom` and `departureUntil` as ISO local datetimes, `stayingNights`, and `ticketOption` (`ROUND_TRIP` or `TWO_ONE_WAY`). The datetime interval is interpreted in the origin airport's local time and its endpoints are inclusive. No UTC offset is accepted by the current request DTO. See [`dto/FlightSearchRequest.java`](../dto/FlightSearchRequest.java) for the exact Bean Validation constraints.

Each itinerary includes segment lists, a total EUR price, and `viewUrls`. A round trip has one Google Flights link. Two one-way tickets have two links, ordered outbound then return. These are search-page references, not guaranteed links to the exact itinerary or a booking transaction. An empty list means no matching result was assembled from the provider responses.

Accommodation search accepts `destinationCity` and `countryCode` from a GeoNames city suggestion, `checkInDate` (ISO date), `stayingNights`, and a total EUR `budget`. For example: `{"destinationCity":"Paris","countryCode":"FR","checkInDate":"2026-12-01","stayingNights":3,"budget":450.00}`. The service validates the city with GeoNames, searches the first SerpApi results page, and fetches details for at most the configured number of affordable properties. Both SerpApi requests use one adult and no children. Each response can include description, address, rating, amenities, and budget-compatible booking-site options. The optional `propertyWebsiteUrl` is the property's own website. A request makes at most one Hotels list search plus one detail search per selected candidate; candidates whose detailed prices exceed the budget are skipped, and successful searches with no eligible properties return `[]`.

Attraction, restaurant, museum, and coffee-shop searches share one city-validation, Google Maps, pagination, and response-mapping flow. Only the provider query differs by category. Each request performs one Google Maps search for the requested page and returns all usable `local_results`, plus `nextPage` when SerpApi offers another page within the supported range. Results include optional place details and safe Google Maps, image, and website URLs. A successful search with no usable local results returns empty `items`; Google Maps results are not guaranteed to fall within city boundaries. Each requested page can consume a separate SerpApi search.

Safety information validates the selected city and country through GeoNames before calling Travel Risk API. It returns country-wide government advisory levels and source links, plus geolocated alerts and recent conflict reports within the configured radius of the city center. The response includes a check time and flags when the provider's first country-results page or displayed local lists may be incomplete. Empty nearby lists do not establish that the city is safe. A check makes up to three Travel Risk API requests and no record is saved.

Country hotlines are read from the imported `emergency_numbers` table. The endpoint validates the country against the local EU `countries` table, does not need a city or make an upstream call, and returns `400` for invalid or unsupported codes. It groups contact rows by provider record ID and puts general emergency entries first. It returns an empty `hotlines` list when the country is supported but no numbers were imported. Verification dates and statuses are source metadata, not live reachability checks.

Destination news validates the city through GeoNames and the country against the local EU table before calling Currents Search. It requests one English-language page of articles mentioning the city from sources in the selected country. It does not guarantee that each article describes conditions inside the city. A successful search with no usable articles returns `[]`; invalid inputs return `400`, unavailable validation or search returns `502`, and unexpected failures return `500`. No provider error body or key is returned.

Destination weather validates the city and country through GeoNames before making one Open-Meteo Forecast request. The response contains local daily dates, weather codes, Celsius high/low temperatures, rain chance and amount, wind speed, and the destination timezone. The window is capped at 14 days and does not imply forecast availability for a later trip. Invalid input returns `400`; unavailable validation or forecast returns `502`.

Saved plans persist search inputs, not flight or accommodation offers. Example create body: `{"title":"Paris weekend","description":"Spring city break","originAirport":"OTP","departureCity":"Bucharest","departureCountryCode":"RO","destinationCity":"Paris","countryCode":"FR","departureFrom":"2027-04-02T08:00:00","departureUntil":"2027-04-04T20:00:00","stayingNights":3,"ticketOption":"ROUND_TRIP","flightBudget":300.00,"accommodationBudget":450.00}`. The departure city and code come from a GeoNames suggestion and are validated; the origin airport must appear in that city's local airport lookup. The plan has no accommodation check-in date; the user chooses it after selecting a flight. Both endpoints require an application JWT, and both responses set `Cache-Control: no-store`. A lookup for another user's UUID returns the same `404` as an unknown UUID.

Error mapping is endpoint-specific: invalid input is generally `400`, an ambiguous local city-airport match is `409`, unavailable city suggestions are `503`, and provider validation/search failures are `502`. Saved-plan creation can also return `401` if the account behind the token no longer exists. Unexpected failures return `500`. See the handlers for the precise messages and covered exception types.
`GET /api/trip-plans/cities/{city}/historical-weather?countryCode=FR&checkInDate=2027-07-01&stayingNights=5` returns the full selected stay for each configured historical comparison year. The city/country pair is checked with GeoNames. Invalid inputs return `400`, unavailable providers return a generic `502`, and provider error bodies are never sent to the client. Historical lookup occurs only on explicit request.
