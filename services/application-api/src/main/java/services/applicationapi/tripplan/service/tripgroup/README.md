# Trip groups and invitations

`TripGroupService` creates a trip group for the authenticated user. `TripGroupServiceImpl` validates and trims its name and optional description, normalizes an optional JPEG or PNG picture, and saves the group, an `ADMIN` membership for its creator, and the picture in one database transaction. A failed validation or write leaves no partial group. Members can list their groups and read one group by ID. Chat and a shared planner are not implemented.

Names are required, at most 100 characters, and cannot contain control characters. Descriptions are optional and at most 1,000 characters; line breaks and tabs are allowed. `TripGroupProperties` bounds upload bytes, decoded pixels, and output dimensions. Images are detected from their contents, re-encoded as JPEG without metadata, and stored in `trip_plan_group_pictures` rather than loaded with every group row.

Group detail and picture reads check membership first. A user who is not a member gets the same `404` response as an unknown group; an absent picture also returns `404`. The application JWT supplies the user ID; request data never selects an owner or initial role. Responses use `Cache-Control: no-store`.

`TripGroupInviteService` handles one-use invitation links. Only an `ADMIN` can create, list, or revoke invites. Creation generates a cryptographically random 32-byte token, returns it once, and persists only its SHA-256 hash. The token is never logged or returned by later list requests. `TripGroupProperties` sets its lifetime and the maximum number of concurrently active invites per group. The service locks the group before counting or changing invites, and locks an invitation before acceptance or revocation, so concurrent requests cannot exceed the active limit or use a link twice. A successful acceptance inserts a `MEMBER` row and marks the invitation used in one transaction. Existing members can open a valid invite without consuming it. Expired, used, revoked, or unknown tokens receive the same generic `404`. The authenticated account is always taken from the JWT.
