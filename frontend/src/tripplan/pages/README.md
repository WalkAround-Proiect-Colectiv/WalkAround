# Trip planning page

`TripPlanningScreen` is a single-page, mobile-first onboarding flow. Users explicitly search for and select GeoNames city suggestions, choose a local departure airport, enter budget, departure dates and times, nights, and ticket style, then inspect selectable flight cards on the same page. They can then search accommodations with the selected destination, staying nights, a separate accommodation budget, and a check-in date from the chosen flight or the calendar. Dates are chosen through `components/CalendarPicker.tsx`; budget, night count, and time fields strip nonnumeric input. Changing an input hides outdated offers. Flight cards expand to show every outbound and return segment and safe Google Flights links; accommodation cards show all returned property details, available booking options, and the separate property website when present.

The final card saves the current search preset with a required title and optional description. The user can save without running either search; the selected provider offers and accommodation check-in date are not stored. Saving validates the form, blocks duplicate taps, shows an error or success on the same page, and resets the success state when a stored input changes. Saving again after an edit creates another plan because the backend currently exposes creation rather than editing. The page is available at `/trip-plan` and requires a signed-in session.
