# Trip planning API client

`tripPlanning.ts` defines the JSON shapes used by the page and calls twelve trip-planning endpoints: city autocomplete, city airports, flight search, accommodation search, saved-plan creation, four place categories, and destination safety. `getPlaceRecommendations` accepts the selected GeoNames destination, a typed category (`attractions`, `restaurants`, `museums`, or `coffee-shops`), and a page number. It calls `GET /api/trip-plans/cities/{city}/{category}?countryCode=...&page=...` and returns `PlaceRecommendationPage` with `items` and nullable `nextPage`. `getDestinationSafety` calls `GET /api/trip-plans/cities/{city}/safety?countryCode=...` only when the user presses **Check safety** or **Refresh safety**. The accommodation request sends the selected destination city/country, first booked night, staying nights, and a separate full-stay EUR budget. Saved-plan creation sends the search preset, title, and optional description, but excludes check-in date and provider offers. The client URL-encodes city names and country codes, sends the current application JWT from the shared session module, applies a 90-second request timeout, and turns backend `ProblemDetail.detail` into a page error. It does not call GeoNames, SerpApi, or Travel Risk API directly or store a token locally.

`getCountryHotlines` calls `GET /api/trip-plans/countries/{countryCode}/hotlines` after a destination is selected. The country code comes from the selected GeoNames suggestion; the backend reads the local emergency-number database. The response groups numbers by hotline and retains channel, organization, category, verification context, provider source, and contact details. A destination change discards the previous result.

`getCityNews` calls `GET /api/trip-plans/cities/{city}/news?countryCode=...` only when the user presses the news button or refreshes it. It uses the selected GeoNames city and country, URL-encodes both values, and receives one page of article metadata with publisher links. The key and Currents request stay on the backend.
