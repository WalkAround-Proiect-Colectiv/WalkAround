# Trip planning API client

`tripPlanning.ts` defines the JSON shapes used by the page and calls thirteen trip-planning endpoints: city autocomplete, city airports, flight search, accommodation search, saved-plan creation, four place categories, destination safety, country hotlines, destination news, and destination weather. `getPlaceRecommendations` accepts the selected GeoNames destination, a typed category (`attractions`, `restaurants`, `museums`, or `coffee-shops`), and a page number. It calls `GET /api/trip-plans/cities/{city}/{category}?countryCode=...&page=...` and returns `PlaceRecommendationPage` with `items` and nullable `nextPage`. `getDestinationSafety` calls `GET /api/trip-plans/cities/{city}/safety?countryCode=...` only when the user presses **Check safety** or **Refresh safety**. The accommodation request sends the selected destination city/country, first booked night, staying nights, and a separate full-stay EUR budget. Saved-plan creation sends the search preset, title, and optional description, but excludes check-in date and provider offers. The client URL-encodes city names and country codes, sends the current application JWT from the shared session module, applies a 90-second request timeout, and turns backend `ProblemDetail.detail` into a page error. It does not call GeoNames, SerpApi, Travel Risk API, Currents, or Open-Meteo directly or store a token locally.

`getCityAirports` returns city matches followed by nearby airports. Each airport includes `matchType` and straight-line `distanceKm`; the backend validates the city through GeoNames and calculates nearby matches from local airport coordinates. Only airports with IATA codes can be selected for flight search.

`getCountryHotlines` calls `GET /api/trip-plans/countries/{countryCode}/hotlines` after a destination is selected. The country code comes from the selected GeoNames suggestion; the backend reads the local emergency-number database. The response groups numbers by hotline and retains channel, organization, category, verification context, provider source, and contact details. A destination change discards the previous result.

`getCityNews` calls `GET /api/trip-plans/cities/{city}/news?countryCode=...` only when the user presses the news button or refreshes it. It uses the selected GeoNames city and country, URL-encodes both values, and receives one page of article metadata with publisher links. The key and Currents request stay on the backend.

`getDestinationWeather` calls `GET /api/trip-plans/cities/{city}/weather?countryCode=...` only when the user requests or refreshes the forecast. It uses the selected GeoNames destination, URL-encodes the city and country code, and receives local daily dates, conditions, Celsius temperatures, precipitation, wind, and timezone. Open-Meteo is called only by the backend.
`getHistoricalWeather` sends the selected destination, check-in date, and stay length to the backend only after the user requests past weather. The response includes complete daily periods for each comparison year; the client does not call Open-Meteo directly.
